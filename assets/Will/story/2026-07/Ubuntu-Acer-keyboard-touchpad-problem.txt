Debug & Solution for the Problem of Unbound I2C Keyboard
==========

# 1: Rebind i2c_designware.2 which is bound to the I2C keyboard 
sudo sh -c 'echo "i2c_designware.2" > /sys/bus/platform/drivers/i2c_designware/unbind && sleep 1 && echo "i2c_designware.2" > /sys/bus/platform/drivers/i2c_designware/bind'
# I2C keyboard: 	i2c_designware.2@ -> /sys/devices/pci0000:00/0000:00:15.3/i2c_designware.2
# I2C touchpad/mouse: 	i2c_designware.0@ -> /sys/devices/pci0000:00/0000:00:15.0/i2c_designware.0
# I2C unknown(?!): 	i2c_designware.1@ -> /sys/devices/pci0000:00/0000:00:15.1/i2c_designware.1

# 2: Re-add modules (doesn't work!)
sudo modprobe -r i2c_hid_acpi  
# i2c_hid_acpi: I2C devices (touch pad, keyboard)
sudo modprobe -r i2c_hid  
# modprobe: FATAL: Module i2c_hid is in use.
# i2c_hid is used by i2c_hid_acpi
sudo modprobe -r hid_generic 
# hid_generic: external devices (mouse, keyboard)
# hid is used by: hid_generic,i2c_hid,hid_multitouch,usbhid,snd_soc_sdca

sudo modprobe i2c_hid_acpi
# Does not fix the binding of the I2C keyboard if bound wrongly before 

# 3: Unbind serio1 which was wrongly bound (doesn't work!)
sudo sh -c 'echo -n "serio1" > /sys/bus/serio/drivers/atkbd/unbind'
# sh: 1: echo: echo: I/O error
# No device bound in atkbd

--------
Solution
-----------------------
/etc/systemd/system/fix-keyboard.service
```ini
[Unit]
Description=Fix Acer I2C Keyboard Recognition
After=multi-user.target

[Service]
Type=oneshot
# Rebind i2c_designware.2 which is bound to the I2C keyboard
ExecStart=/bin/sh -c 'echo "i2c_designware.2" > /sys/bus/platform/drivers/i2c_designware/unbind && sleep 1 && echo "i2c_designware.2" > /sys/bus/platform/drivers/i2c_designware/bind'
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

systemd-analyze verify /etc/systemd/system/fix-keyboard.service
sudo systemctl daemon-reload
sudo systemctl enable fix-keyboard.service
sudo systemctl start fix-keyboard.service

Touchpad
------------------ 
Note: Lower number has higher precedence in disabling touchpad.
0. Hardware: fn F9
   Persist across boots and takes effect across OS switch.
1. OS-level: echo 1 | sudo tee /sys/class/input/input?/inhibited
   + Enable: echo 0 | sudo tee /sys/class/input/input?/inhibited
   + Note: This takes effect at boot, so at login screen, but does NOT PERSIST across boots.
2. GUI: GNOME Settings > Mouse & Touchpad > Touchpad tab > toggle it!
   Persist across boots.
   This takes effect only after logged in, not at login screen.
2'. Session-level: gsettings set org.gnome.desktop.peripherals.touchpad send-events 'disabled'
   This is the underlying mechanism of number 2, and its change will be reflected live to the GUI.
