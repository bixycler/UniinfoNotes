# Plan: Code Exploration of Logseq Markdown to CommonMark Converter

We have completed a comprehensive read-only exploration of the `logseqmd2commonmark.js` script, its shared utility module `common-utils.js`, and its corresponding test suite and test input files.

## 1. Objectives & Scope
- **Task**: The user requested to check and read `logseqmd2commonmark.js` and its related files.
- **Scope**: Fully read-only, understanding the pipeline that converts Logseq's customized outliner markdown (with bullet nesting, block-level properties, inline math, and specific metadata block types) into standard CommonMark.

## 2. Findings and Architecture Summary
- **Converter (`logseqmd2commonmark.js`)**: Parses command-line arguments, loads/saves the global `index.json`, processes blocks topologically to flatten/resolve nested title references, handles empty blocks, and generates properly compliant `.cm.md` CommonMark outputs while preserving block links.
- **Utilities (`common-utils.js`)**: Contains helper functions like `escapeXML`, `slugify`, code-block preprocessors (`preprocessCodeBlocks`), and line indexers (`indexLines`), as well as prototype enhancements for JavaScript primitives.
- **Test Suite (`logseqmd2commonmark-test-suite.md` / `logseqmd2commonmark-test.md`)**: Documents and tests 10 distinct bugs/edge cases, including:
  1. First heading de-itemization
  2. Inline `id::` properties
  3. Spaces in output links
  4. `--break` option escaping block elements
  5. `logseq-meta` anchor placement around fences
  6. Empty bullets rendering as indented blocks (solved with `&nbsp;`)
  7. Block title UUID topological resolution
  8. True positive circular transclusion references
  9. False positive circular references inside markdown link targets
  10. Sibling `id::` fallback contamination
