# Fix: `resolveTitleReferences()` corrupting titled links & false circular refs

## Problem

`PAT_REF` in `resolveTitleReferences()` (common-utils.js:354) matches `((uuid))` blindly — even inside markdown links `[text](((uuid)))`. Two bugs:

1. **Title corruption**: Replacement turns `[text](((uuid)))` into `[text]RESOLVED_TITLE` — broken link syntax.
2. **False circular refs**: UUIDs inside titled links are added as dependency edges, creating phantom cycles that trigger the "Circular refs detected" fallback.

## Scope boundary

`PAT_REF` is a **local variable** inside `resolveTitleReferences()` — not exported. Only used at lines 363, 394, 429 of `common-utils.js`. The function is called from:
- `build-index.js:147` — global index build
- `logseqmd2commonmark.js:500` — per-file conversion

No other code is affected. The converter's link-rendering patterns (`PAT_UUID_REF`, `PAT_BRACKET_UUID_REF`, `PAT_LINK_REF`) are separate and unchanged.

## Fix (common-utils.js:354)

Add negative lookbehind `(?<!\]\() ` to the `((uuid))` alternative:

```js
// Before:
const PAT_REF = /\(\(([0-9a-fA-F-]{36})\)\)|\[\[([0-9a-fA-F-]{36})\]\]/g;
// After:
const PAT_REF = /(?<!\]\()\(\(([0-9a-fA-F-]{36})\)\)|\[\[([0-9a-fA-F-]{36})\]\]/g;
```

In `[text](((uuid)))`, the inner `((uuid))` is always preceded by `](` — the lookbehind excludes it. Bare `((uuid))` has no preceding `](`, so it's matched normally. The `[[uuid]]` alternative is unchanged.

## Test cases (logseqmd2commonmark-test.md)

Append two new sections after existing section 7:

### Section 8: Titled link in a block title that is cross-referenced
```markdown
- 8.1 Target for titled link test
  id:: 33333333-3333-3333-3333-333333333331
- 8.2 Block whose title includes a titled link: [details](((33333333-3333-3333-3333-333333333331)))
  id:: 33333333-3333-3333-3333-333333333332
- 8.3 Reference to 8.2: ((33333333-3333-3333-3333-333333333332))
```
Expect: 8.2's title preserves `[details](((uuid)))` intact. 8.3 renders link text as `[details](((3333...331)))` — i.e., the title of block 8.2, which IS `[details](((3333...331)))`.

### Section 9: False circular ref via titled link
```markdown
- 9.1 Target A
  id:: 44444444-4444-4444-4444-444444444441
- 9.2 Target B that titled-links to A: [see A](((44444444-4444-4444-4444-444444444441)))
  id:: 44444444-4444-4444-4444-444444444442
- 9.3 Block referencing B: ((44444444-4444-4444-4444-444444444442))
```
Expect: No "Circular refs" warning. 9.3 resolves to `[see A](((4444...441)))` correctly.
