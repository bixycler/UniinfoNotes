## Problem scope (Fix C)

When a Logseq block has no inline title (e.g. `- id:: uuid` with nothing between `- ` and `id::`), current `indexLines()` falls back to `lastContentLine` or filename. Logseq itself treats the block's content as the block title — blockquotes, `#+BEGIN_*` macros, code blocks — the "mirror/transclusion" feature.

Currently these blocks' titles are all filenames:

| UUID | Actual content | Current title (wrong) |
|------|---------------|----------------------|
| `67baf59b-...` | `> 3blue1brown gives an excellent "mirror reflection" analogy...` | `"2025 Stories"` |
| `67850fd2-...` | `#+BEGIN_CAUTION` … `[:b ...]` … `#+END_CAUTION` | `"Task"` |
| `66f6b7c0-...` | `search-scope-page:: [[Mind Jungle]]…` / `search-scope:: ((uuid))` | `"2024 Brainstorms"` |
| `66bad570-...` | Vietnamese prose paragraph | `"2024 Stories"` |

## Design

### 1. Refactor `preprocessCodeBlocks` → `preprocessStructuredBlocks`

All four structured constructs collapsed to placeholder tokens by the preprocessor (not handled inline):

| Raw construct | Token | Detection rule |
|---|---|---|
| `` ```code`` ``` | `__CODE_BLOCK_N__` | Unchanged from original |
| `> l1 / l2 / > / l3` | `__BLOCKQUOTE_N__` | Starts at first `>` line; continues through all subsequent **non-blank** lines (lazy continuations without `>` included); ends at blank line |
| `#+BEGIN_<TYPE>` … `#+END_<TYPE>` | `__ORG_BLOCK_N__` | Starts at `#+BEGIN_`; scans forward to matching `#+END_` |
| `*:: value` / `:LOGBOOK:`…`:END:` | `__PROPS_BLOCK_N__` | Contiguous lines matching `PAT_PROP` or `PAT_LB_START`/`PAT_LB_END` |

#### Props block detection (4th type)

Detected inside the same line-scanning loop using existing patterns:

```javascript
// PAT_PROP (already exists):
/^\s*(\w+):: (.*)$/

// LOGBOOK markers (already exist):
PAT_LB_START = /^\s*:(logbook|LOGBOOK):$/;
PAT_LB_END   = /^\s*:END:$/;
```

Contiguous sequence of lines matching any of these → single `__PROPS_BLOCK_N__`. Ends at first non-matching line. The original lines are stored in `blockMap[token].lines`.

Returns `{ cleanLines, blockMap }` where `blockMap[token] = { type: string, lines: string[] }` (plain object, replaces old `codeBlockMap` Map).

Callers update:
- `build-index.js`: rename call + destructure `blockMap` instead of `codeBlockMap`
- `logseqmd2commonmark.js`: same rename + expand `__BLOCKQUOTE_*` and `__ORG_BLOCK_*` in `convertFile()` via `expandBlockToken()`

### 2. Props block expansion in `convertFile()`

`convertFile()` sees `__PROPS_BLOCK_N__` instead of individual property lines. Expand by feeding original lines through the existing PAT_PROP/LOGBOOK detection:

```
if token starts with "__PROPS_BLOCK_" and blockMap[token] exists:
  for each original line in blockMap[token].lines:
    if PAT_LB_START → inLogbook = true; continue
    if PAT_LB_END → inLogbook = false; continue
    if inLogbook → accumulate into logbook string; continue
    if PAT_PROP → accumulate into props object; continue
  continue (skip to next clean line — lines consumed into metadata)
```

The `<a class="logseq-meta">` anchor is emitted when the next content line hits (unchanged from current behavior).

### 3. Title = first structured block only, with system-props filtering

In `indexLines()`, when bare `- id:: uuid` has no inline title, scan subsequent clean lines:

1. If next line is a structured-block token (`__BLOCKQUOTE_`, `__ORG_BLOCK_`, `__CODE_BLOCK_`, `__PROPS_BLOCK_`): expand via `blockMap` → potential title.
2. If it is a regular content line: use that line (trimmed) as potential title.
3. If it is a sibling bullet at same/shallower indent: stop (no content found).
4. For `__PROPS_BLOCK_`: after expansion, **filter out** system properties and LOGBOOK:
   - `id:: ...` (system prop)
   - `collapsed:: ...` (system prop)
   - `:LOGBOOK:` / `:END:` and all logbook lines between them
   - Keep all other user properties (`search-scope::`, `tags::`, etc.)
5. If no content survives filtering: existing fallback (parent `lastContentLine` or filename).
6. `lastContentLine` inheritance: use first non-system-property, non-empty content line.

`indexLines()` signature gains optional 3rd param `blockMap`.

### 4. New helper: `expandBlockToken(token, blockMap)`

Returns `block.lines.join('\n')` or the token itself if not found. Used by `convertFile()` for `__BLOCKQUOTE_*` / `__ORG_BLOCK_*` / `__PROPS_BLOCK_*` tokens.
