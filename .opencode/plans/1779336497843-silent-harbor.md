# Fixes

Two independent but related fixes to the indexing/title-resolution pipeline:

## Fix A: PAT_REF in `resolveTitleReferences()` (already applied + verified)

`PAT_REF` in `common-utils.js:354` matched `((uuid))` inside `[text](((uuid)))`, causing corruption and false circular refs. Fixed with negative lookbehind.

## Fix B: `lastContentLine` fallback inheriting from sibling blocks

### Problem

`indexFileBlocks` (build-index.js:60–84) and `indexInternalBlocks` (logseqmd2commonmark.js:97–117) use a flat `lastContentLine` accumulator that doesn't track indentation. When a block is just `- id:: uuid` (no visible title), the fallback `title || lastContentLine` grabs content from the **last non-id bullet** at any nesting level — including **siblings**. This causes:

1. **Self-referencing titles**: If a sibling happens to reference the same UUID (e.g., `[directed (bent)](((uuid)))`), the title inherits that self-reference.
2. **Wrong titles**: A bare `id::` block inherits a sibling's content instead of its actual parent's content.

### Root cause

```js
// For a bare `- id:: uuid` line:
const title = content.replace(idMatch[0], '').trim(); // = "" (empty, no extra text)
blocks[uuid] = { title: title || lastContentLine, ... }; // falls back to lastContentLine
```

`lastContentLine` is updated blindly on every non-id bullet (line 83), regardless of indentation:
```js
lastContentLine = content || lastContentLine; // overwritten by siblings!
```

### Fix

Track indentation alongside content. Only fall back to `lastContentLine` when it's from a **parent** level (shallower indent), not a sibling or deeper.

Logic change in both `indexFileBlocks` and `indexInternalBlocks`:
- Add `let lastContentIndent = -1;`
- Compute `const curIndent = line.length - line.trimStart().length;`
- For bare `- id:: uuid` (title is empty): fall back to `lastContentLine` only if `lastContentIndent < curIndent` (it's from a parent), otherwise use file basename.
- Don't update `lastContentLine` for bare `id::` blocks (they have no visible content to propagate).
