## Problem scope (Fix C)

When a Logseq block has no inline title (e.g. `- id:: uuid` with nothing between `- ` and `id::`), current `indexLines()` falls back to `lastContentLine` or filename. Logseq itself treats the block's content as the block title — blockquotes, `#+BEGIN_*` macros, code blocks — the "mirror/transclusion" feature.

Currently these blocks' titles are all filenames:

| UUID | Actual content | Current title (wrong) |
|------|---------------|----------------------|
| `67baf59b-...` | `> 3blue1brown gives an excellent "mirror reflection" analogy...` | `"2025 Stories"` |
| `67850fd2-...` | `#+BEGIN_CAUTION` … `[:b ...]` … `#+END_CAUTION` | `"Task"` |
| `66bad570-...` | Vietnamese prose paragraph | `"2024 Stories"` |

## Design

### 1. Refactor `preprocessCodeBlocks` → `preprocessStructuredBlocks`

All three structured constructs collapsed to placeholder tokens by the preprocessor (not handled inline):

| Raw construct | Token | Detection rule |
|---|---|---|
| `` ```code`` ``` | `__CODE_BLOCK_N__` | Unchanged from original |
| `> l1 / l2 / > / l3` | `__BLOCKQUOTE_N__` | Starts at first `>` line; continues through all subsequent **non-blank** lines (lazy continuations without `>` included); ends at blank line |
| `#+BEGIN_<TYPE>` … `#+END_<TYPE>` | `__BEGIN_BLOCK_N__` | Starts at `#+BEGIN_`; scans forward to matching `#+END_` |

Returns `{ cleanLines, blockMap }` where `blockMap[token] = { type: string, lines: string[] }` (plain object, replaces old `codeBlockMap` Map).

Callers update:
- `build-index.js`: rename call + destructure `blockMap` instead of `codeBlockMap`
- `logseqmd2commonmark.js`: same rename + expand `__BLOCKQUOTE_*` and `__BEGIN_BLOCK_*` in `convertFile()` via `expandBlockToken()`

### 2. Title = first structured block only, with attribute exclusion

In `indexLines()`, when bare `- id:: uuid` has no inline title, scan subsequent clean lines:

1. Skip property lines (`PAT_PROP`: `collapsed::`, `tags::`, etc.) and logbook markers (`PAT_LB_START`/`PAT_LB_END`) — these are `logseq-meta` metadata, not content.
2. If next non-property line is a structured-block token: expand via `blockMap` → title.
3. If it is a regular content line: use that line (trimmed) as title.
4. If no content found (only properties until end or sibling bullet): existing fallback.
5. `lastContentLine` inheritance: use first non-property content line.

`indexLines()` signature gains optional 3rd param `blockMap`.

### 3. New helper: `expandBlockToken(token, blockMap)`

Returns `block.lines.join('\n')` or the token itself if not found. Used by `convertFile()` for `__BLOCKQUOTE_*` / `__BEGIN_BLOCK_*` tokens.

## Example

Input:
```markdown
- id:: 67baf59b-...
  > 3blue1brown gives an excellent "mirror reflection" analogy…
```

After preprocessing: `>` block collapsed to `__BLOCKQUOTE_0__`.
`indexLines()` sees `- id:: uuid`, next line is `__BLOCKQUOTE_0__` → expands via `blockMap` → title = `"> 3blue1brown gives an excellent \"mirror reflection\" analogy…"`

Before: `"2025 Stories"` (filename)  
After: `"> 3blue1brown gives an excellent \"mirror reflection\" analogy…"`
