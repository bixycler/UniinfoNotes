# Fixes: title-resolution pipeline + bare `- id::` block title transclusion

## Fix C: Structured-block transclusion for bare `- id::` blocks

### Problem scope

When a Logseq block has no inline title (e.g. `- id:: uuid` with nothing between `- ` and `id::`), our current `indexLines()` falls back to the parent's `lastContentLine` or the filename as the block title. But Logseq itself treats all the content below the `- id::` line (the rest of the block) as the block title — blockquotes, `#+BEGIN_*` macros, properties, child bullets, code blocks, everything. This is the "transclusion/mirror" feature inherited from RemNote.

Currently these blocks' titles are all just filenames, losing the transcluded content:

| UUID | Actual block content | Current title (wrong) |
|------|-------------------|----------------------|
| `67baf59b-...` | `> 3blue1brown gives an excellent "mirror reflection" analogy...` | `"2025 Stories"` |
| `67850fd2-...` | `#+BEGIN_CAUTION` … `[:b ... " Back to WORK! "]` … `#+END_CAUTION` | `"Task"` |
| `66f6b7c0-...` | `search-scope-page:: [[Mind Jungle]]` … `collapsed:: true` | `"2024 Brainstorms"` |
| `66bad570-...` | `2. Theo nghĩa rộng hơn một chút,` … Vietnamese prose | `"2024 Stories"` |

### Design decision 1: title = first structured block, NOT entire item

The look-ahead for a bare `- id:: uuid` title should NOT consume the entire list item (all continuation lines + nested children until next bullet at same/shallower indent). Instead, it should collect only the **first structured block** following the `- id::` line:

- If the next line(s) form a blockquote (`> ...`), the title is just those `>` lines.
- If the next lines are a `#+BEGIN_`/`#+END_` block, the title is just that block.
- If the next line is a `` ```code``` `` fence, the title is just that code block.
- If the next line is plain text (no structure), stop at the first line.
- Nested child bullets (`- child` at deeper indent) are **not** part of the title.

Rationale: using the entire multi-line item as a title would be unwieldy for link previews, slugs, and the index. The first structured block captures the semantic content without inflating the title with children.

### Design decision 2: preprocess blockquotes/`#+BEGIN_` like code blocks

Handling blockquotes and `#+BEGIN_`/`#+END_` inline in `indexLines()` and `convertFile()` would fragment conversion logic across both functions. Instead, **refactor `preprocessCodeBlocks()` into `preprocessStructuredBlocks()`** that collapses all three structured constructs into placeholder tokens:

| Raw construct | Collapsed token | Type |
|---|---|---|
| `` ``` … ``` `` | `__CODE_BLOCK_N__` | `code` |
| `> … > …` (contiguous) | `__BLOCKQUOTE_N__` | `blockquote` |
| `#+BEGIN_<TYPE>` … `#+END_<TYPE>` | `__BEGIN_BLOCK_N__` | `begin-block` |

The return value changes from `{ cleanLines, codeBlockMap }` to `{ cleanLines, blockMap }` where `blockMap` is `Object<token, {type: string, lines: string[]}>` (a plain object, not a Map, for serializability).

### Solution

In `indexLines()`: when a `- id:: uuid` line has **no inline title** (`title` is empty after stripping `id:: uuid`), instead of immediately falling back to parent/filename, **look ahead** at the next clean line(s) to collect the first structured block as the transcluded title.

**Algorithm** (inside the existing loop):

1. `i` is at a `- id:: uuid` line, `title` is empty (no inline text).
2. Look at the next clean line at index `i+1`:
   - If it is a structured-block token (`__BLOCKQUOTE_`, `__BEGIN_BLOCK_`, `__CODE_BLOCK_`): collect its lines from `blockMap`, join with `\n` → title.
   - If it is a regular content line: use that single line as the title (trimmed).
   - If there is no next line: existing fallback (parent `lastContentLine` or filename).
3. For `lastContentLine` inheritance: use the **first non‑property line** of the collected content (so child blocks inherit a clean single-line parent title, not the entire multi-line block).
4. If no content lines found at all → existing fallback.

**`indexLines()` signature change**: accepts an optional 3rd parameter `blockMap`.

### Caller updates
- `build-index.js` `indexFileBlocks()`: use `preprocessStructuredBlocks()`, pass `blockMap` to `indexLines()`.
- `logseqmd2commonmark.js`: use `preprocessStructuredBlocks()`, pass `blockMap` through `indexInternalBlocks()`.
- `convertFile()`: expand `__BLOCKQUOTE_N__` and `__BEGIN_BLOCK_N__` tokens the same way it already does for `__CODE_BLOCK_N__`.

Input:

#### 7. `indexLines(filePath, cleanLines, blockMap)` — the core fix

Core iteration logic with:
- Indent-aware `lastContentLine` fallback (sibling contamination fix).
- Structured-block transclusion for bare `- id::` blocks (Fix C).

```js
function indexLines(filePath, cleanLines, blockMap) {
  const results = {};
  let lastContentLine = path.basename(filePath, '.md');
  let lastContentIndent = -1;

  for (let i = 0; i < cleanLines.length; i++) {
    const { line, originalIndex } = cleanLines[i];
    const curIndent = line.length - line.trimStart().length;
    const stripped = line.trim();

    // Skip all structured-block tokens
    if (stripped.startsWith('__CODE_BLOCK_') ||
        stripped.startsWith('__BLOCKQUOTE_') ||
        stripped.startsWith('__BEGIN_BLOCK_')) continue;

    if (stripped.startsWith('- ')) {
      let content = stripped.substring(2).trim();
      const idMatch = content.match(PAT_ID_PROP);
      if (idMatch) {
        const uuid = idMatch[1];
        const inlineTitle = content.replace(idMatch[0], '').trim();
        let effectiveTitle;
        let firstContentLine = '';

        if (inlineTitle) {
          effectiveTitle = inlineTitle;
          lastContentLine = inlineTitle;
          lastContentIndent = curIndent;
        } else {
          // Bare - id:: → scan forward, skip properties/logbook,
          // stop at first structured block or content line
          for (let j = i + 1; j < cleanLines.length; j++) {
            const next = cleanLines[j];
            const nextStripped = next.line.trim();

            // Skip properties and logbook markers
            if (next.line.match(PAT_PROP) ||
                next.line.match(PAT_LB_START) ||
                next.line.match(PAT_LB_END)) continue;

            // Stop at sibling bullet (end of this block's content)
            if (nextStripped.startsWith('- ') &&
                next.line.length - next.line.trimStart().length <= curIndent) break;

            // Structured-block token → expand from blockMap
            if (blockMap && blockMap[nextStripped]) {
              const block = blockMap[nextStripped];
              effectiveTitle = block.lines.join('\n');
              firstContentLine = block.lines.find(l => l.trim() && !l.match(PAT_PROP)) || '';
              break;
            }

            // Regular content line
            if (nextStripped && !nextStripped.startsWith('__')) {
              effectiveTitle = nextStripped;
              firstContentLine = nextStripped;
              break;
            }
          }

          if (!effectiveTitle) {
            effectiveTitle = lastContentIndent < curIndent
              ? lastContentLine
              : path.basename(filePath, '.md');
          }

          if (firstContentLine) {
            lastContentLine = firstContentLine;
            lastContentIndent = curIndent;
          }
        }

        results[uuid] = { title: effectiveTitle, sourceLine: originalIndex + 1 };
      } else {
        lastContentLine = content || lastContentLine;
        lastContentIndent = curIndent;
      }
    } else {
      const idMatch = stripped.match(PAT_ID_PROP);
      if (idMatch && lastContentLine) {
        results[idMatch[1]] = { title: lastContentLine, sourceLine: originalIndex + 1 };
      }
    }
  }
  return results;
}
```

## Changes in detail

### common-utils.js — structural changes

#### Rename: `preprocessCodeBlocks` → `preprocessStructuredBlocks`
- Same code fence logic, plus two new constructs:
- **Blockquotes (`>` lines)**: MD syntax defines a blockquote as the first `>` line plus all subsequent contiguous **non-blank** lines (lazy continuation lines without `>` are part of the same blockquote). A blank line ends it. Collapse to `__BLOCKQUOTE_N__`.
- **`#+BEGIN_`/`#+END_` blocks**: when a line starts with `#+BEGIN_`, scan forward until `#+END_`, collapse to `__BEGIN_BLOCK_N__`.
- Return value changes from `{ cleanLines, codeBlockMap }` to `{ cleanLines, blockMap }` where `blockMap` keys are tokens, values are `{ type: string, lines: string[] }`.

##### Blockquote collapsing examples

```
> l1            → triggers start
l2              → lazy continuation (no `>`), included
>               → empty quote line, included
l3              → lazy continuation, included
(blank line)    → ends the blockquote
```

Result: single `__BLOCKQUOTE_N__` containing all 4 lines.

```
> standalone

> another
```

Two separate `__BLOCKQUOTE_N__` tokens (blank line separates them).

#### New: `expandBlockToken(token, blockMap)`
- Looks up a token in `blockMap`, returns `block.lines.join('\n')`.
- If not found, returns the token itself (safe passthrough).

#### New: 5 shared helper functions
- `normalizePageHeader(rawLines)` — mutates rawLines[0] in place
- `loadIndex(indexFile)` — returns parsed JSON or `{}`
- `saveIndex(indexFile, globalIndex)` — writes with mkdir
- `parseArgValue(args, i, flag)` — returns `{ value, i }` or exits
- `indexLines(filePath, cleanLines, blockMap?)` — indent-aware fallback + structured-block transclusion (Fix C)

**`indexLines` logic change**: signature gains optional 3rd param `blockMap`. When a `- id:: uuid` line has no inline title, scan subsequent clean lines to find the first content:

1. Skip property lines (`PAT_PROP`: `collapsed::`, `tags::`, etc.) and logbook markers (`PAT_LB_START`/`PAT_LB_END`) — these are `logseq-meta` metadata, not content.
2. If the next non-property line is a structured-block token (`__BLOCKQUOTE_`, `__BEGIN_BLOCK_`, `__CODE_BLOCK_`): expand via `blockMap` for the transcluded title.
3. If it is a regular content line: use that line (trimmed) as the title.
4. If no content line found (only properties until end or sibling bullet): existing fallback (parent `lastContentLine` or filename).
5. For `lastContentLine` inheritance: use the first non-property, non-empty content line.

All added to `module.exports`.
